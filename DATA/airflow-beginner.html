Airflow 첫걸음: 완전 초보 입문서

2026-09-22 · Imm

Airflow를 처음 만지는 사람이 하루 안에 "내 작업을 Airflow에 올려서 돌려 봤다"까지 가는 것이 목표입니다. 어려운 용어와 운영 설정은 빼고, 꼭 필요한 것만 순서대로 다룹니다.

1. Airflow가 뭔가요?

한 줄 정의: Airflow는 "정해진 순서대로, 정해진 시간에, 일을 시키고 결과를 기록하는" 작업 관리자입니다.

식당 주방에 비유해 보겠습니다.

주방 Airflow
레시피 (재료 손질 → 볶기 → 담기) DAG: 작업 순서를 적은 파이썬 파일
레시피의 한 단계 ("양파 썰기") Task: 순서 속 작업 하나
주방장 (언제 무엇을 시작할지 결정) Scheduler
요리사 (실제로 손을 움직임) Worker
주방 모니터 (어느 요리가 어디까지 됐는지) 웹 화면(UI)

왜 cron 대신 Airflow를 쓰나요?

cron으로도 "매일 새벽 2시에 스크립트 실행"은 됩니다. 하지만 일이 여러 개로 늘어나면 곧 이런 질문에 답하기 어려워집니다.

  • A가 끝난 다음에 B를 돌리고 싶다
  • 어젯밤 작업이 실패했는지 아침에 한눈에 보고 싶다
  • 실패하면 자동으로 몇 번 다시 시도했으면 좋겠다
  • 지난주 3일치를 다시 돌리고 싶다

Airflow는 이 네 가지를 기본으로 해 줍니다.

꼭 기억할 것: Airflow는 일을 시키는 쪽이지 일을 하는 쪽이 아닙니다. 대용량 데이터 처리는 Spark나 DB에 맡기고, Airflow는 "언제, 어떤 순서로"만 관리하는 것이 올바른 사용법입니다.

2. 꼭 알아야 할 단어 6개

처음에는 이 여섯 개만 알면 됩니다. 나머지 용어는 필요할 때 찾아보세요.

단어 뜻 예
DAG 작업 묶음과 그 순서. 파이썬 파일 하나로 작성 "매출 집계" 작업 전체
Task DAG 안의 작업 한 조각 "데이터 내려받기", "합계 내기"
Operator Task를 만드는 틀. 무엇을 실행할지의 종류 파이썬 함수 실행, 리눅스 명령 실행, SQL 실행
스케줄 DAG를 언제 돌릴지 매일 새벽 2시, 매시간, 사람이 버튼 눌렀을 때만
Run (DAG Run) DAG를 한 번 실행한 것 "9월 22일 새벽 2시 실행분"
로그 Task가 실행되며 출력한 기록 print() 내용, 에러 메시지

관계를 그림으로 보면 이렇습니다. 화살표는 "앞이 끝나야 뒤가 시작된다"는 뜻입니다.

이 세 개의 네모와 화살표를 통틀어 DAG 하나라고 부릅니다. DAG는 "방향이 있고 되돌아가는 고리가 없는 그래프(Directed Acyclic Graph)"의 줄임말인데, "C가 끝나면 다시 A로" 같은 무한 반복은 만들 수 없다는 정도만 알면 충분합니다.

3. 내 컴퓨터에 설치하고 화면 열기

연습용으로는 airflow standalone 명령 하나면 충분합니다. 필요한 구성 요소를 한 번에 띄워 줍니다. 회사 서버에는 이미 설치돼 있을 테니, 이 장은 "내 노트북에서 자유롭게 망가뜨리며 연습하는 환경" 만들기입니다.

준비물: macOS 또는 Linux, Python 3.10 이상. Windows라면 WSL2(윈도우 안의 리눅스)에서 하세요. Airflow는 Windows에서 직접 돌지 않습니다.

3.1 설치

bash
# 1) 연습용 폴더를 만들고 들어간다
mkdir airflow-practice && cd airflow-practice

# 2) 가상환경 만들기: 이 폴더 전용 파이썬 환경 (다른 프로젝트와 섞이지 않게)
python3 -m venv .venv
source .venv/bin/activate        # 프롬프트 앞에 (.venv)가 보이면 성공

# 3) Airflow가 자기 파일을 둘 위치를 이 폴더로 지정
#    (지정 안 하면 ~/airflow 가 쓰인다)
export AIRFLOW_HOME=$(pwd)

# 4) 설치. --constraint는 "이 버전과 잘 맞는 라이브러리 버전 목록"이다.
#    빼면 설치는 되더라도 실행 중에 이상한 에러가 나기 쉽다.
AIRFLOW_VERSION=3.3.2
PYTHON_VERSION=$(python3 -c 'import sys; print(f"{sys.version_info.major}.{sys.version_info.minor}")')
pip install "apache-airflow==${AIRFLOW_VERSION}" \
  --constraint "https://raw.githubusercontent.com/apache/airflow/constraints-${AIRFLOW_VERSION}/constraints-${PYTHON_VERSION}.txt"

3.2 실행

bash
# 예제 DAG 수십 개가 화면을 채우지 않도록 끄고 시작 (궁금하면 나중에 True로)
export AIRFLOW__CORE__LOAD_EXAMPLES=False

airflow standalone

처음 실행하면 데이터베이스를 만드느라 1분 정도 걸립니다. 로그 사이에 로그인 비밀번호가 출력됩니다. 놓쳤다면 AIRFLOW_HOME 폴더의 simple_auth_manager_passwords.json.generated 파일에서 확인할 수 있습니다.

이제 브라우저에서 http://localhost:8080 을 열고 admin / 출력된 비밀번호로 로그인합니다.

3.3 생긴 파일 살펴보기

text
airflow-practice/          ← AIRFLOW_HOME
├── airflow.cfg            ← 설정 파일 (지금은 건드리지 않아도 됨)
├── airflow.db             ← 실행 기록이 저장되는 DB (SQLite)
├── logs/                  ← 태스크 로그
└── dags/                  ← ★ 여기에 DAG 파일을 넣는다 (없으면 만들기)

dags/ 폴더가 없다면 직접 만드세요. 이 폴더에 둔 파이썬 파일을 Airflow가 자동으로 읽어 갑니다.

bash
mkdir -p dags

다음 날 다시 시작할 때는 cd airflow-practice && source .venv/bin/activate && export AIRFLOW_HOME=$(pwd) 후 airflow standalone. 종료는 터미널에서 Ctrl+C.

4. 첫 번째 DAG 만들기

"인사하고 → 숫자를 세고 → 끝났다고 말하는" 세 단계 DAG를 만들어 봅니다. 실제로는 아무 일도 하지 않지만, Airflow의 기본 동작은 전부 들어 있습니다.

4.1 파일 만들기

dags/hello_airflow.py 파일을 만들고 아래 내용을 그대로 붙여넣습니다.

python
# dags/hello_airflow.py

# Airflow에서 DAG와 Task를 만드는 도구 2개를 가져온다
from airflow.sdk import dag, task


# @dag: 바로 아래 함수가 "DAG"라고 Airflow에 알려 주는 표시
@dag(
    dag_id="hello_airflow",   # 화면에 표시될 이름. 영문·숫자·밑줄만
    schedule=None,            # 자동 실행 안 함. 버튼을 눌렀을 때만 실행
    tags=["연습"],           # 화면에서 찾기 쉽게 붙이는 꼬리표 (생략 가능)
)
def hello_airflow():

    # @task: 바로 아래 함수가 "Task 하나"라는 표시
    #        함수 이름(say_hello)이 곧 Task 이름이 된다
    @task
    def say_hello():
        print("안녕하세요, Airflow!")   # print한 내용은 로그에서 볼 수 있다

    @task
    def count():
        for i in range(1, 4):
            print(f"{i}번째 숫자")

    @task
    def say_bye():
        print("끝!")

    # 순서 정하기. >> 는 "왼쪽이 끝나면 오른쪽을 실행"
    # 함수 뒤에 ()를 붙여야 Task가 만들어진다 (빼먹기 쉬움!)
    say_hello() >> count() >> say_bye()


# 마지막으로 DAG 함수를 한 번 호출해야 Airflow가 이 DAG를 등록한다
hello_airflow()

파일 구조를 한 번 더 정리하면 이렇습니다.

  1. @dag를 붙인 함수 하나 = DAG 하나
  2. 그 안에 @task를 붙인 함수들 = Task들
  3. >>로 순서 연결
  4. 맨 아래에서 DAG 함수 호출

4.2 화면에 나타나길 기다리기

파일을 저장하고 30초\~1분 뒤 브라우저를 새로고침하면 DAG 목록에 hello_airflow가 나타납니다. Airflow는 dags/ 폴더를 주기적으로 다시 읽기 때문에 바로 보이지는 않습니다.

1분이 지나도 안 보이면 파일에 오타가 있는 것입니다. 화면 상단에 빨간 Import Error 알림이 뜨거나, 터미널에서 직접 확인할 수 있습니다.

bash
# 파이썬 문법 오류부터 확인 (아무 출력 없으면 문법은 정상)
python dags/hello_airflow.py

# Airflow가 읽다가 실패한 파일과 이유를 보여준다
airflow dags list-import-errors

4.3 실행하기

  1. DAG 목록에서 hello_airflow를 클릭합니다.
  2. 오른쪽 위 Trigger(▶) 버튼을 누릅니다.
  3. 잠시 후 세 네모가 차례로 초록색이 되면 성공입니다.

DAG가 회색 토글로 일시정지(Paused) 상태인지 확인하세요. 새 DAG는 기본으로 일시정지 상태로 등록될 수 있고, 이 경우 버튼을 눌러도 대기만 합니다. 토글을 켜 주세요.

터미널에서 화면 없이 바로 돌려 볼 수도 있습니다. 코드를 고칠 때마다 빠르게 확인하기에 좋습니다.

bash
# DAG 전체를 지금 바로 한 번 실행하고, 모든 로그를 터미널에 출력한다
airflow dags test hello_airflow

5. 화면 읽는 법

웹 화면에서 처음에 볼 곳은 세 군데뿐입니다.

5.1 DAG 목록

등록된 DAG들이 한 줄씩 나오는 첫 화면입니다. 확인할 것은 두 가지입니다.

  • 토글(켜짐/꺼짐): 꺼져 있으면 스케줄도, 버튼 실행도 진행되지 않습니다.
  • 최근 실행 상태: 마지막 Run이 성공했는지 실패했는지 색으로 표시됩니다.

5.2 Grid 화면 (가장 많이 보는 화면)

DAG를 클릭하면 나오는 바둑판 모양 화면입니다.

  • 세로 줄 하나 = Run 하나 (오른쪽일수록 최근)
  • 가로 줄 하나 = Task 하나
  • 칸 하나 = 그 Run에서 그 Task가 실행된 결과

칸의 색깔이 상태를 알려 줍니다.

색 상태 뜻
초록 success 성공
빨강 failed 실패 (재시도도 다 쓰고 최종 실패)
연두 running 지금 실행 중
회색 queued / scheduled 순서를 기다리는 중
노랑 up_for_retry 실패해서 재시도를 기다리는 중
주황 upstream_failed 앞 Task가 실패해서 시작조차 못 함
분홍 skipped 조건에 따라 건너뜀

색상은 버전·테마에 따라 조금씩 다를 수 있습니다. 칸에 마우스를 올리면 상태 이름이 글자로 나오니 그걸 믿으세요.

주황(upstream_failed)을 보면 그 Task가 아니라 앞쪽의 빨간 칸을 찾으세요. 원인은 항상 빨간 칸에 있습니다.

5.3 로그 보기

  1. Grid에서 보고 싶은 칸을 클릭합니다.
  2. 오른쪽에 열리는 패널에서 Logs 탭을 엽니다.
  3. 코드의 print() 출력과 에러 메시지가 여기 나옵니다.

에러 로그는 보통 길게 출력됩니다. 맨 아래에서 위로 읽으며 Error 또는 Exception이 들어간 첫 줄을 찾으면 대부분 원인이 거기 있습니다.

연습 삼아 count 태스크에 1 / 0을 일부러 넣고 실행해 보세요. 빨간 칸, 주황 칸, ZeroDivisionError 로그를 한 번에 볼 수 있습니다.

6. 한 발짝 더: 자주 쓰는 세 가지

첫 DAG를 돌렸다면, 실무에서 바로 필요한 것은 이 세 가지입니다.

6.1 Task끼리 값 넘기기

앞 Task가 return한 값을 뒤 Task가 인자로 받을 수 있습니다. 이때는 >>를 쓸 필요 없이, 함수를 호출하듯 연결하면 순서도 자동으로 정해집니다.

python
from airflow.sdk import dag, task

@dag(dag_id="pass_values", schedule=None)
def pass_values():

    @task
    def get_numbers():
        return [3, 5, 7]          # 이 값이 Airflow에 저장되어 다음 Task로 전달된다

    @task
    def add_up(numbers):          # 앞 Task의 return 값이 numbers로 들어온다
        total = sum(numbers)
        print(f"합계: {total}")
        return total

    @task
    def report(total):
        print(f"보고: 오늘 합계는 {total}입니다")

    # get_numbers → add_up → report 순서로 실행되고, 값도 차례로 전달된다
    report(add_up(get_numbers()))

pass_values()

주의: 이렇게 넘기는 값은 Airflow의 데이터베이스에 저장됩니다(XCom이라고 부릅니다). 숫자, 짧은 문자열, 파일 경로 정도만 넘기세요. 수백 MB짜리 표를 통째로 넘기면 느려지고 고장납니다. 큰 데이터는 파일이나 테이블에 저장하고 그 위치만 넘깁니다.

6.2 매일 자동으로 실행하기

schedule에 실행 주기를 적고, start_date로 언제부터 유효한지 정합니다.

python
import pendulum                       # 시간대가 포함된 날짜를 만드는 라이브러리 (Airflow에 포함)
from airflow.sdk import dag, task

@dag(
    dag_id="daily_hello",
    schedule="0 9 * * *",            # 매일 09:00 (아래 표 참고)
    start_date=pendulum.datetime(2026, 9, 1, tz="Asia/Seoul"),  # 한국 시간 기준
    catchup=False,                    # 지나간 날짜는 몰아서 실행하지 않음
)
def daily_hello():

    @task
    def greet(ds=None):
        # 인자 이름을 ds로 쓰면 Airflow가 이번 실행의 날짜('2026-09-22' 형식)를 넣어 준다
        print(f"{ds} 아침 인사")

    greet()

daily_hello()

schedule에 들어가는 cron 표현식은 분 시 일 월 요일 다섯 칸입니다.

쓰고 싶은 것 값
매일 09:00 "0 9 * * *"
매시간 정각 "0 * * * *" 또는 "@hourly"
평일(월\~금) 18:30 "30 18 * * 1-5"
매월 1일 00:00 "0 0 1 * *" 또는 "@monthly"
자동 실행 안 함 None

헷갈릴 때는 crontab.guru에서 표현식을 넣어 보면 우리말처럼 풀어 줍니다.

catchup이 뭔가요? start_date가 9월 1일이고 오늘이 9월 22일이면, catchup=True일 때 Airflow는 "밀린 21일치"를 한꺼번에 실행합니다. 초보 때는 항상 catchup=False로 두세요.

6.3 실패하면 다시 돌리기

자동 재시도. 네트워크가 잠깐 끊기는 식의 일시적 실패는 잠시 후 다시 하면 대부분 성공합니다.

python
from datetime import timedelta

@task(
    retries=2,                          # 실패하면 최대 2번 더 시도 (총 3번)
    retry_delay=timedelta(minutes=1),   # 다시 시도하기 전에 1분 기다림
)
def fetch_data():
    ...

손으로 다시 돌리기 (Clear). 코드를 고친 뒤 실패한 부분만 다시 실행하는 방법입니다.

  1. Grid에서 빨간 칸을 클릭합니다.
  2. Clear 버튼을 누릅니다. "이 칸을 아직 실행 안 한 상태로 되돌리기"라는 뜻입니다.
  3. Downstream 옵션을 켜 두면 뒤따라오는 Task도 함께 다시 실행됩니다.
  4. 확인을 누르면 Airflow가 그 칸부터 다시 실행합니다.

Clear는 이미 성공한 앞쪽 Task를 다시 돌리지 않습니다. 그래서 오래 걸리는 앞 단계를 또 기다릴 필요가 없습니다.

7. 초보가 자주 하는 실수 7가지

# 증상 원인 해결
1 DAG가 화면에 안 나타남 파일이 dags/ 밖에 있거나, 맨 아래 DAG 함수 호출(hello_airflow())을 빠뜨림 파일 위치와 마지막 줄 확인. 1분 기다리기
2 빨간 Import Error 문법 오류, 설치 안 된 라이브러리 import python dags/파일.py로 먼저 실행해 보기
3 Trigger를 눌렀는데 아무 일도 없음 DAG가 일시정지(토글 꺼짐) 상태 목록에서 토글 켜기
4 순서가 이상하거나 Task가 빠짐 say_hello >> count처럼 ()를 빠뜨림 say_hello() >> count()
5 스케줄 켜자마자 수십 개가 한꺼번에 실행됨 catchup=True + 오래전 start_date catchup=False
6 매번 같은 날짜 데이터만 처리됨 / 재실행하면 엉뚱한 날짜 코드에서 datetime.now()로 날짜를 구함 Airflow가 주는 ds를 사용
7 화면이 느려지고 DAG 반영이 늦음 함수 밖(파일 맨 위)에서 DB 조회나 API 호출 그런 코드는 모두 @task 함수 안으로

7번은 이유를 알아두면 좋습니다. Airflow는 DAG 파일을 30초마다 다시 읽습니다. 파일 맨 위에 둔 코드는 그때마다 실행되지만, @task 함수 안의 코드는 실제로 그 Task가 실행될 때만 돌아갑니다.

python
# 나쁜 예: 파일을 읽을 때마다(30초마다) API를 호출한다
import requests
items = requests.get("https://example.com/items").json()

@task
def process():
    print(items)

# 좋은 예: Task가 실행될 때 한 번만 호출한다
@task
def process():
    import requests
    items = requests.get("https://example.com/items").json()
    print(items)
